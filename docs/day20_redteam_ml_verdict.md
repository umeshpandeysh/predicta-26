## 2. Most Important Question Answered

### Question:
*"Did Predicta learn semiconductor behavior, or did it primarily learn the synthetic dataset's defect-generation rules?"*

### Red Team Verdict:
**MIXED EVIDENCE WITH SYNTHETIC SHORTCUT DEPENDENCIES**

1. **What Predicta Learned Correctly (Physical Monotonicity)**:
   Feature perturbation analysis proves that Predicta learned true physical monotonicity. Incrementally increasing physical measurements (`leakage_current`, `temperature`, `propagation_delay`) smoothly and monotonically increases failure probability, correctly transitioning from `PASS` through `SECONDARY_TEST` to `FAIL`.

2. **Synthetic Shortcut Dependencies**:
   XGBoost decision tree splits heavily rely on high-severity defect parameter shifts generated by `generate_dataset.py`. Because `equipment_id` was assigned randomly without tying to equipment drift severity, the model failed to learn equipment-context drift (`EQUIPMENT_DRIFT` recall = 31.85%).

---

## 3. Recommended Fixes for Future Iterations (Post-Production)

1. **Equipment Drift Ingestion**: Modify data generator to tie chamber sensor drift directly to `equipment_id` so one-hot features encode machine degradation.
2. **Probability Recalibration**: Apply Platt scaling or isotonic regression to align probabilities with empirical failure frequencies.
3. **Real Fab ATE Calibration**: Ingest real fab SECS/GEM wafer ATE logs to replace synthetic distribution assumptions.
